## Project context

- What every Krizaka macOS app (Tauri 2) shares, written once. Governance of `krizaka/krizaka-rust`; decision: [ADR-005](https://github.com/krizaka/.github/blob/main/docs/adr/ADR-005-tauri-app-kit.md).
- Kind: `rust` · team: `krizaka` · registry entry: [repos.json](https://github.com/krizaka/.github/blob/main/repos.json).
- Two crates. The **rules** (folder scope, files, the drop gate, the navigation guard, deep links, the menu checks, secrets, settings, the update channel) are the root crate `krizaka-rust`: pure Rust, no `tauri` dependency, tested on any machine. The **glue** that applies them (commands, events, the Keychain, the native menu, `RunEvent::Opened`) is `plugin/` (`tauri-plugin-krizaka`); it decides nothing the root crate does not check.
- Not here: a product's commands, its sidecar, its messages, its brand. Those are the product's, started from [`krizaka-template`](https://github.com/krizaka/krizaka-template) (target `desktop`).
- The page side of the plugin is `@krizaka/app-desktop` (krizaka-ui): its `COMMANDS` list and `plugin/build.rs` change together.
- `CLAUDE.md` is the one line `@AGENTS.md`: never a second copy of this file.

## Essential commands

```bash
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
git diff --exit-code -- plugin/permissions   # the generated permissions are committed as the build writes them
site/build.sh /tmp/site                      # preview of rust.krizaka.com (home, FR and EN)
```

- Run them on what you changed before every push; CI (`.github/workflows/rust.yml`, on macOS) runs the same four checks.

## Architecture & conventions

- Follow the [krizaka-engineering skill](https://github.com/krizaka/krizaka-agents/blob/main/plugins/krizaka-engineering/skills/krizaka-engineering/SKILL.md); search its [packages reference](https://github.com/krizaka/krizaka-agents/blob/main/plugins/krizaka-engineering/skills/krizaka-engineering/references/packages.md) before writing anything generic.
- Send every read through `ScopeStore::resolve`; never use a path from the UI directly.
- Put no product word, no network and no environment read in these crates: values arrive as parameters (`Builder`). One named exception: `scope::home_dir()` reads `HOME` (the plugin's one entry point); every rule takes the home as a parameter (`*_with_home`), so every refusal is tested without the environment.
- Make a limit a per-call parameter (`files::Limits`): the app passes it, the kit has a default and a hard ceiling for each; a value above the ceiling is lowered, never obeyed. Sort a list, then cut it.
- Add a file type as one line in `files::TYPES`, the one table that gives a file's kind and MIME.
- Dates and times: `time` 0.3, never `chrono` (unmaintained, RUSTSEC-2026-0543; `jiff` is pre-1.0). Pass the clock in; never an ambient `now()` in a rule (krizaka-internal#4159).
- Name things by what they do; no `*Utils`, `*Helper`, `*Manager`.

## Guard-rails & known pitfalls (read before coding)

- Treat a change to what may be granted or to the guard's rules as breaking: apps in the wild depend on it.
- Give every refusal a test: `..`, a symlink out of a grant, a never-grantable folder, a look-alike host.
- Change `COMMANDS` of `@krizaka/app-desktop` and `plugin/build.rs` together; commit the regenerated `plugin/permissions/autogenerated/` (CI fails on a diff in `plugin/permissions`).
- Cut a release as a tag `vX.Y.Z`; products pin the tag.
- The checks are the judge ([ADR-015](https://github.com/krizaka/krizaka-internal/blob/main/docs/adr/.github/ADR-015-ai-code-audit-measured-and-enforced.md), [guards](https://github.com/krizaka/.github/blob/main/docs/standards/guards.md)): never `--no-verify`, never a raised ratchet or baseline; a rule is never silenced to get green.
- Anti-slop, what a model tends to write and the code does not need:
  - A closed set is a type (enum, sealed interface, `as const` object), never a string compared by hand.
  - No `*Utils`, `*Helper` or `*Manager` (ArchUnit, ADR-015 §5).
  - Use `?.` and `??` in TypeScript, not a chain of `&&` or a ternary on null.
  - (Java rules of ADR-015 — `@NullMarked`, DTO records, `ProblemDetail` — do not apply to this Rust repository.)
- Start a fix with a failing test; every bug gets its guard.
- Never invent a URL, a law article, a price or a figure you did not read; write `TO VALIDATE` and say who decides.
- Never commit a secret, a capture or a log; no production data in a session, only the dev data.
- Keep the edit hook in `.claude/settings.json`: `npx --yes -p @krizaka/config krizaka-edit-check` on `Edit|Write` (`npx --no-install krizaka-edit-check` where `@krizaka/config` is a dependency).

## Expected validation workflow

- [ ] Format, lint and test what changed (the commands above); fix the cause of a red, never the guard.
- [ ] Concurrency: a « count then insert » or « check then write » runs under one lock and has a concurrency test.
- [ ] One gate: a rule (limit, permission, validation) is enforced in the service, so no route skips it; test every route.
- [ ] Errors: a cleanup (rollback, drop, close) never masks the original error.
- [ ] Validation: validate the original input, never a truncated or pre-trimmed copy; server and client reject the same inputs.
- [ ] Accessibility and words (page-side changes): every control has a unique label, FR/EN pairs say their language, every user-facing string is in the FR and EN messages, no hard-coded colour.
- [ ] Environment variables follow `<CONTEXT>_<THING>` (`APP_`, `DATABASE_`, `AUTH_`, `MEDIA_`, `MAIL_`, `PAYMENTS_`, `AI_`…) and are declared once.
- [ ] A feature or fix PR names its journey (`Journey: <name>` or `Journey: n/a — <reason>`); README and generated docs still say what the code does.
- [ ] Answer every review thread: fix it test-first, or reply with the reason, then resolve it.
- [ ] One issue, one small PR; merge only with green CI.
